# 中学受験算数の追加計画

## 学年と追加順

学校算数の道すじとは別に「中学受験」の学習順を用意する。学年はアプリの推奨配当であり、学校の標準配当ではない。四則計算・単位の理解を前提に、4年生は整数で関係を整理し、5年生は割合・比・速さ、6年生は複合問題に進む。

| 段階    | 推奨学年                 | 単元                                                  | 状態     |
| ------- | ------------------------ | ----------------------------------------------------- | -------- |
| 第1段階 | 4年                      | 和差算・植木算・鶴亀算・差集め算・過不足算・消去算    | 追加済み |
| 第2段階 | 4年                      | 周期算・規則性                                        | 次の候補 |
| 第3段階 | 5年                      | 倍数算・比の分配・年齢算・相当算・還元算              | 追加済み |
| 第4段階 | 5年                      | 売買損益・食塩水・旅人算・通過算                      | 追加済み |
| 第5段階 | 5年：流水算／6年：仕事算 | 流水算・仕事算                                        | 追加済み |
| 第6段階 | 6年                      | ニュートン算・3種類の鶴亀算・比と年齢・速さの複合問題 | 追加済み |

参考： [四谷大塚4年上の学習予定表](https://www.yotsuyaotsuka.com/kyozai/pdf/4th_grade/2026_4.pdf)、[5年上の学習予定表](https://www.yotsuyaotsuka.com/kyozai/pdf/5th_grade/2026_5_sp.pdf)。

## 4年生追加の実装手順と受け入れ条件

1. 6単元の表示名・説明・推奨学年・難易度を既存の教材レジストリへ登録し、「中学受験」カテゴリで選べるようにする。
2. 専用の生成モジュールを追加する。答えとなる整数から条件を作り、負数・端数・条件不足を避ける。乱数の両端や一定値でも終了するよう、再抽選ループを使わない。
3. 既存の生成入口から呼び出す。学習順は「和差算・植木算 → 鶴亀算・差集め算 → 過不足算・消去算」。学校算数の道すじと切り替えられるようにする。
4. 解答表示時だけ考え方と計算手順を表示する。問題用紙に解答や途中計算を出さない。既存の式記入欄・印刷・URL復元を利用する。
5. 問題文の条件から独立に解き直すテスト、各条件の出題、乱数境界、登録・表示・学習順・解答の非表示、A4の実測を検証する。

| 単元     | 出題の変化                            | 数値の設計                                       |
| -------- | ------------------------------------- | ------------------------------------------------ |
| 和差算   | 大きい数／小さい数を求める            | 小さい数と差から合計を作る                       |
| 植木算   | 両端・片端・両端なし・輪              | 間隔と間の数から全長を作る。両端なしでも木が残る |
| 鶴亀算   | 動物の足／2種類の買い物               | 両方の個数を正整数にし、合計個数と合計量を作る   |
| 差集め算 | 単価の差／1日あたりの量の差           | 1つあたりの差×個数から全体の差を作る             |
| 過不足算 | 余る→足りない／両方余る／両方足りない | 同じ人数・総数に対して2つの配り方を作る          |
| 消去算   | そのまま引く／整数倍してそろえる      | 2種類の単価を決め、独立した2つの購入条件を作る   |

共通の実装範囲は問題の生成と解答手順。線分図・面積図を使った解説付き例題、図の穴埋め練習、自力で図を作る練習は教材の次の拡張として扱う。4年生の周期算・規則性と図形（面積の分割・移動、相似と面積比、立体の切断）も後続の追加対象とする。

## 4年生追加時の実装と検証結果

6単元の生成は `src/lib/generators/entrance-exam.ts`、登録は `src/config/entrance-exam-patterns.ts` に実装した。既存の追加教材レジストリ・生成入口と接続し、4年生の教材は84種類から90種類になった。開始条件を巡回ごとに変えることで、少ない問題数でも同じ条件だけに偏らないようにしている。

学習順は `ENTRANCE_LEARNING_PATHS` と `LearningPath` に、解答表示時のみの解き方表示は `ProblemList` に実装した。図解の追加は後続の範囲として残る。

## 5・6年生への拡張

5年生に10単元、6年生に5単元を追加した。計算の前提は各学年の学校算数で練習し、受験コースでは比・割合の先取りを含めて文章題を解く。4年生の6単元を合わせ、受験教材は21単元になった。

| 学年 | 単元                  | 出題条件                                             |
| ---- | --------------------- | ---------------------------------------------------- |
| 5    | 比の分配              | 2人の分配／2つの比をそろえて3人の分配                |
| 5    | 倍数算                | やりとりで合計が一定／同じ数を増やして差が一定       |
| 5    | 年齢算                | 指定の倍数になる何年後／何年前                       |
| 5    | 還元算                | 倍にして足す操作／引く・割る・足す操作の逆算         |
| 5    | 相当算                | 全体の一部を読んだ残り／残りの一部をさらに読む       |
| 5    | 売買損益              | 利益を求める／利益から原価を求める／損失を求める     |
| 5    | 食塩水                | 異なる濃度・量の混合／水だけを加えて薄める           |
| 5    | 旅人算                | 向かい合って出会う／同時に進んで追いつく             |
| 5    | 通過算                | 列車が橋を完全に通過する／2列車がすれ違う            |
| 5    | 流水算                | 静水と流れの速さから下り／上りの時間                 |
| 6    | 仕事算                | 初めから共同作業／1人が先に働き、残りを共同作業      |
| 6    | ニュートン算          | 2つの処理条件から流入量／制限時間に必要な人数        |
| 6    | 鶴亀算の応用（3種類） | 3種類の合計・足の数・2種類の個数の関係を組み合わせる |
| 6    | 比と年齢の複合問題    | 現在の比と合計／差から、将来の比になる年を求める     |
| 6    | 速さの複合問題        | 遅れて出発して追いつく／出会う前に片方の速さが変わる |

生成は `entrance-exam-upper.ts`、共通の文章題構築・最大公約数・最小公倍数は `entrance-exam-shared.ts` に置き、既存の `generateEntranceExamProblems` から呼び出す。登録・学習順・解答表示・URL復元は4年生と同じ仕組みを使う。教材数は5年生61→71、6年生61→66。

数値は答えから条件を組み立てる。2段階の相当算では各段階のページ数、割合では円・食塩の量、仕事算では1日分の仕事量まで整数になるようにする。売買損益の損失は負の利益でなく、損失額を正の数で答える。上りの速さ、追いつきの速さの差、仕事の残量は正にし、再抽選ループを使わない。

受け入れ条件は、全15単元の独立した問題文の解き直しと乱数境界、学年の登録と学習順、コース切替と次の教材、解き方の非表示、最大問題数でのA4印刷。解説の長さに合わせ、5・6年生の推奨・最大問題数は1列3問・2列4問・3列3問とする。

### PDF出力の再検証

上記の初回検証では、受験教材のサンプルPDFをアプリ画面から直接生成していた。印刷時にプレビューが非表示になるため、実際には白紙だったが、ページ数だけのチェックで見逃していた。用紙寸法の確認は有効だが、当初のサンプルPDFの内容確認は不十分だった。

検証スクリプトを修正し、アプリの印刷ボタンが作るiframeの内容を取得してPDFを生成する。最終出力の用紙・問題数・解き方の表示有無・用紙寸法・列のはみ出しに加え、PDFが1ページであることと描画された文字を含むことを確認する。

- `node scripts/check-curriculum-print.mjs http://127.0.0.1:5174/ --pattern-prefix=entrance- --max-values`：成功。最大の数値・最大問題数・式記入欄付きで全21単元×3列設定×解答有無の126条件を実際にPDF化し、各A4・1ページであることを確認。学年別サンプル3件も含め、計129 PDFを検証。結果は `summary-max-values.json`、全条件のPDFは `.playwright-cli/curriculum-check/entrance-pdfs/` に保存。
- 4・5・6年生のサンプルPDFを `pdfinfo` と `pdftotext` で確認。A4・1ページで問題文と解答を含む。`pdftoppm` で画像に変換し、文字切れ・列の重なりがないことを目視確認。従来の学年別サンプルPDFも実際の印刷内容で上書きした。
- 既存の印刷iframeからの複数枚出力もA4・3ページで成功。はみ出した場合に印刷を中止する検証も成功。
- 変更したスクリプトの `eslint`・`prettier --check`、`git diff --check` は成功。アプリ本体の変更はなく、単体テスト・本番ビルドは再実行していない。
